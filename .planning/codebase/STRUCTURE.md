## Directory Purposes

**`agent/`:**
- Purpose: Everything that runs on the Raspberry Pi
- Contains: Single-file agent script, VERSION, config example, systemd unit
- Key files: `timelapse_agent.py` (the entire agent implementation)

**`server/app/`:**
- Purpose: FastAPI application package
- Contains: Main routes module, supporting modules for render queue, agents, DSLR discovery, SSH provisioning
- Key files: `main.py` (dominant — contains all routes and models), `render_queue.py` (async rendering)

**`server/app/static/v2/`:**
- Purpose: Served SPA frontend (no build step, vanilla ES modules)
- Contains: Entry HTML, router/shell JS, view modules, component modules, CSS
- Key files: `app.js` (router + shared API), `views/dashboard.js` (main landing), `views/camera.js` (per-camera detail)

**`server/data/`:**
- Purpose: Runtime persistence directory; excluded from git in production
- Contains: Camera config JSON, captured images, thumbnails, rendered videos, agent SSH keys and manifests, release tarballs
- Key files: `config.json` (sole persistent store for camera records)

**`tests/`:**
- Purpose: pytest test suite split by component
- Contains: Agent unit tests (pure function tests, no server), server integration tests (FastAPI `TestClient`)
- Key files: `conftest.py`, `tests/server/fixtures/dslr/*.json` (per-vendor gphoto2 output fixtures)

**`scripts/`:**
- Purpose: Developer and operator tooling
- Contains: Release build, dev server, host install/update, test simulation scripts

**`docs/`:**
- Purpose: Product requirements, feature specs, design sketches
- Contains: PRD, discovery sketches, CI environment notes, superpowers planning docs

## Key File Locations

**Entry Points:**
- `server/app/main.py`: FastAPI `app` object — all HTTP routes
- `agent/timelapse_agent.py`: `main()` function — agent process entry

**Configuration:**
- `server/data/config.json`: Camera records (config + live status); created automatically
- `/etc/timelapse-agent/config.json`: Agent config on Pi (camera_id, server_url, etc.)
- `server/systemd/timelapse-server.service`: Server systemd unit — sets `TIMELAPSE_DATA_DIR`, port, allowed networks
- `agent/systemd/timelapse-agent.service`: Agent systemd unit on Pi

**Core Logic:**
- `server/app/main.py`: Camera CRUD, checkin, frame upload/download, provisioning orchestration
- `server/app/render_queue.py`: `RenderRunner` class — async ffmpeg execution with progress
- `agent/timelapse_agent.py`: `run_agent()` — main loop, capture, upload, scheduling

**Testing:**
- `tests/conftest.py`: Shared fixtures
- `tests/server/`: Server endpoint tests via `TestClient`
- `tests/agent/`: Agent pure-function unit tests

## Naming Conventions

**Files:**
- Python modules: `snake_case.py` (e.g. `render_queue.py`, `ssh_provision.py`)
- JS views: `kebab-case.js` under `views/` (e.g. `create-agent.js`, `dashboard.js`)
- JS components: `kebab-case.js` under `components/` (e.g. `schedule.js`, `sidebar.js`)
- Tests: `test_<module_or_feature>.py`

**Directories:**
- Python packages: `snake_case/` with `__init__.py`
- Data subdirectories: match the conceptual noun (`images/`, `videos/`, `agents/`, `releases/`)

## Where to Add New Code

**New API endpoint:**
- Add route handler and any new Pydantic models in `server/app/main.py`
- If the feature requires significant logic (>~50 lines), extract to a new module in `server/app/<feature>.py` and import it
- Add corresponding tests in `tests/server/test_<feature>.py`

**New agent feature:**
- All agent code lives in `agent/timelapse_agent.py` — add functions and wire them into `run_agent()`
- Add tests in `tests/agent/test_<feature>.py` (pure function tests, no mocking of the whole agent)

**New view in the SPA:**
- Create `server/app/static/v2/views/<view-name>.js`
- Export a `render<ViewName>(root)` function and call `registerView("/<prefix>", render<ViewName>)` at the module level
- Import the view module in `server/app/static/v2/app.js` (lazy import or static import at top)

**New reusable UI component:**
- Create `server/app/static/v2/components/<component-name>.js`
- Export a `mount<ComponentName>(host, opts)` function that renders into the given host element

**New data persisted server-side:**
- Camera-level fields: add to `CameraConfig` or `CameraStatus` Pydantic models in `main.py`; they round-trip automatically through `data/config.json`
- Agent-level fields: add to the `PendingAgent` dataclass in `agents.py` and update `manifest.json` writer

**Release artifacts:**
- Stage a new agent tarball in `server/data/releases/` (or the production equivalent at `/srv/timelapse/releases/`)
- Set `desired_agent_version` on a camera's config to trigger OTA update

## Special Directories

**`server/.venv/`:**
- Purpose: Production virtualenv for the server
- Generated: Yes (by `scripts/install-server.sh` or manual `pip install`)
- Committed: No (gitignored)

**`.venv-dev/`:**
- Purpose: Dev/test virtualenv used by `scripts/dev-server.sh` and pytest
- Generated: Yes
- Committed: No (gitignored)

**`dev-data/`:**
- Purpose: Local development data directory with sample config and images
- Generated: Partially (images captured locally)
- Committed: Config committed; `images/` and `videos/` are gitignored

**`.planning/codebase/`:**
- Purpose: GSD codebase map documents consumed by `/gsd-plan-phase` and `/gsd-execute-phase`
- Generated: Yes (by `/gsd-map-codebase` command)
- Committed: Yes

**`agent/__pycache__/`, `server/app/__pycache__/`, `tests/**/__pycache__/`:**
- Purpose: Python bytecode cache
- Generated: Yes
- Committed: No (gitignored)
